Параллельные сессии Claude Code в нескольких репозиториях

Grove — приложение в строке меню и утилита командной строки для macOS. Он выделяет каждой фиче проекта из нескольких репозиториев своё рабочее пространство (workspace): один каталог, где лежит git worktree каждого выбранного вами репозитория, и все они на одной ветке. Claude Code, запущенный в этом каталоге, видит весь продукт, а параллельные сессии никогда не мешают друг другу переключением веток. Интерфейс приложения — на английском.

А ещё Grove показывает ваши сессии Claude Code во всех проектах и аккаунтах и переносит сессию с одного аккаунта Claude на другой.

Рабочее пространство на каждую фичу: git worktree каждого репозитория на одной ветке

Claude Code лучше всего работает, когда видит весь продукт в одном каталоге. Если продукт разнесён по нескольким репозиториям, параллельные сессии начинают спотыкаться о ветки: одна переключает ветку в репозитории сервера — и вторая, занятая другой фичей, вдруг видит не тот код.

Рабочее пространство Grove — это каталог для одной фичи, в котором лежит git worktree каждого выбранного вами репозитория, и все они на одной ветке. Claude Code запускается в этом каталоге с собственной рабочей копией всего продукта, и ничто из того, что делает другая сессия, не может сменить ветку у него под ногами.

# запускайте Claude Code здесь:
~/Workspaces/acme-shop/checkout-redesign/
├── web-client/     feat/checkout-redesign
├── api-server/     feat/checkout-redesign
└── server-config/  feat/checkout-redesign

Что такое git worktree?

Git worktree — это дополнительный рабочий каталог репозитория: со своими файлами и своей текущей веткой, но с общей историей и общими удалёнными репозиториями. Если у каждой сессии Claude Code свой worktree, одна сессия может делать фичу, пока другая чинит баг. Рабочее пространство Grove делает то же самое сразу для всех репозиториев продукта, в одном каталоге.

Рабочие пространства Grove и claude --worktree

Настройка рабочего пространства под ваш проект

  • Ветки от нужной точки. Каждый репозиторий стартует со своей базовой ветки (она определяется по origin/HEAD или задаётся для репозитория вручную) либо с веток другого рабочего пространства, поэтому рабочие пространства можно наслаивать.
  • Имена веток по шаблону, по умолчанию feat/{name}.
  • Общие файлы в каждом рабочем пространстве. Файлы вроде CLAUDE.md попадают в каждое новое рабочее пространство ссылкой или копией — в его корень или в каждый репозиторий.
  • Хуки после создания. Каждый репозиторий может выполнить в своём новом worktree собственную команду оболочки.
  • Параметры запуска по умолчанию. У каждого проекта есть аккаунт Claude, модель и уровень effort по умолчанию.
  • Состояние на виду. У каждого рабочего пространства видны возраст, незакоммиченные изменения и сессии.

Все сессии Claude Code перед глазами — по проектам и аккаунтам

Grove находит сессии Claude Code каждого проекта и рабочего пространства во всех ваших аккаунтах. Он показывает, какие сессии запущены, какие ждут вас, а какие закрыты. На экране Projects один клик переводит вас к запущенной сессии — в cmux или Terminal.app.

  • Новые и возобновлённые. В окне запуска выбираются аккаунт, модель и уровень effort, и сессия открывается в cmux или Terminal.app.
  • Сгруппированы по тому, где идёт работа: по проектам и рабочим пространствам, с веткой и аккаунтом каждой сессии.

Перенос сессии Claude Code на другой аккаунт

Claude Code хранит каждый аккаунт в отдельной папке: ~/.claude для аккаунта по умолчанию и ~/.claude-accounts/<name> для каждого аккаунта, добавленного в Grove. Сессия не обязана оставаться на том аккаунте, с которого началась. Продолжайте её под другим своим аккаунтом, например, когда у одного из них кончился лимит.

Resume as…
Продолжает сессию под другим аккаунтом, ничего не копируя: связанные аккаунты пользуются общими папками сессий через ~/.claude.
Migrate to…
Копирует сессию в другой аккаунт (транскрипт, память, историю файлов, задачи), даже если этот аккаунт сейчас используется.
Share
Переносит сессию в общее хранилище, где её видят все связанные аккаунты.
Один процесс на сессию
Grove не выполнит перенос, после которого в сессию писали бы два процесса сразу: например, не возобновит под одним аккаунтом сессию, которая ещё запущена под другим.

По шагам это описано в руководстве «Как продолжить сессию Claude Code под другим аккаунтом» (на английском).

Транскрипты, которые переживают 30-дневную очистку Claude Code

Claude Code удаляет транскрипты сессий старше cleanupPeriodDays, по умолчанию это 30 дней. Grove хранит жёсткую ссылку на каждый транскрипт в ~/.claude/grove/transcripts/ и восстанавливает пропавший из аккаунта транскрипт, кто бы его ни удалил: вы или очистка Claude Code. По умолчанию транскрипты хранятся до 90 дней и занимают не больше 500 МБ.

В Settings → Transcript safety-net можно изменить оба ограничения или выключить зеркало. Purge на экране Sessions удаляет транскрипт насовсем.

Граф коммитов и статистика кода по репозиториям

Graph
Граф коммитов каждого репозитория с ветками, удалёнными репозиториями и тегами. Из ветки можно создать рабочее пространство или открыть Claude Code в её worktree.
Stats
Строки кода по всему проекту: итоги, разбивка по языкам и рост во времени на диаграмме с накоплением по репозиториям.

CLI grove: worktree нескольких репозиториев из терминала или скрипта

Утилита командной строки grove работает с теми же рабочими пространствами. Команды: scan, workspaces, sessions, create, graph и doctor; каждая принимает флаг --json.

# репозитории и их worktree
grove scan ~/code/acme-shop

# рабочие пространства проекта в виде дерева
grove workspaces ~/code/acme-shop

# рабочее пространство с двумя репозиториями
grove create ~/code/acme-shop loyalty-points \
  --repos api-server,web-client

# сессии в каталоге, в формате JSON
grove sessions ~/Workspaces/acme-shop/loyalty-points --json

# установлены ли git, claude и cmux?
grove doctor

CLI использует схему Grove по умолчанию, ~/Workspaces/<project>/<name> на ветке feat/<name>, а не настройки отдельных проектов из приложения.

Grove подходит для продукта, разнесённого по нескольким репозиториям, если вы работаете над ним с Claude Code на Mac — под одним аккаунтом или под несколькими.

Частые вопросы

Как запустить несколько сессий Claude Code параллельно, чтобы они не мешали друг другу?

Дайте каждой задаче свою рабочую копию — git worktree; Anthropic описывает этот способ для параллельных сессий. Если продукт разнесён по нескольким репозиториям, рабочее пространство Grove собирает worktree каждого из них на одной ветке. Запустите Claude Code в этом каталоге.

Может ли Claude Code работать с несколькими репозиториями сразу?

Флаг --add-dir даёт сессии доступ к дополнительным каталогам, а permissions.additionalDirectories делает этот доступ постоянным. Так открывается доступ к файлам, но большую часть конфигурации .claude/ из этих каталогов Claude Code не подхватывает. Рабочее пространство Grove собирает все репозитории, уже переключённые на ветку фичи, в том каталоге, где запускается Claude Code. Подробнее — в руководстве «Как запустить Claude Code сразу в нескольких репозиториях» (на английском).

Чем рабочее пространство Grove отличается от claude --worktree?

Смотрите таблицу выше. Если коротко, --worktree работает с одним репозиторием, а рабочее пространство — со всеми выбранными вами репозиториями сразу, на одной ветке.

Можно ли выбрать базовую ветку, имя ветки и папку для каждого рабочего пространства?

Да. У каждого репозитория своя базовая ветка, имена веток берутся из шаблона, а корневой каталог рабочего пространства тоже задаётся шаблоном.

Как CLAUDE.md и другие общие файлы попадают в каждое рабочее пространство?

Укажите их в настройках проекта, в разделе Workspaces & seeds. Grove добавляет их в каждое новое рабочее пространство ссылкой или копией — в его корень или в каждый репозиторий.

Как продолжить сессию Claude Code под другим аккаунтом?

  • Resume as… продолжает её под другим аккаунтом, ничего не копируя.
  • Migrate to… делает полную копию.
  • Share переносит её в общее хранилище.

Grove не выполнит перенос, после которого в одну сессию писали бы два процесса. Подробнее — в руководстве «Как продолжить сессию Claude Code под другим аккаунтом» (на английском).

Пропадёт ли история сессий, если сменить аккаунт?

Связанные аккаунты пользуются общими папками сессий через ~/.claude, поэтому сессия, начатая под одним связанным аккаунтом, видна остальным. Учётные данные, настройки и плагины у каждого аккаунта свои.

Почему пропадают старые сессии Claude Code и можно ли их сохранить?

Claude Code удаляет транскрипты старше cleanupPeriodDays, по умолчанию это 30 дней. Зеркало транскриптов в Grove по умолчанию хранит их до 90 дней и в пределах 500 МБ, и его можно выключить.

Сколько сессий Claude Code можно запустить одновременно?

Собственного ограничения в Grove нет. Каждая сессия расходует лимиты того аккаунта, под которым запущена. Grove показывает сессии по проектам и рабочим пространствам и отмечает, какие запущены, а какие ждут вас.

Нужен ли cmux?

Рекомендуется, но не обязателен. Окно запуска умеет открывать сессию в Terminal.app; остальные кнопки, которые запускают или возобновляют сессию, например Resume и Resume as…, открывают её в cmux. Кроме того, Claude Code можно самостоятельно запустить в рабочем пространстве из любого терминала.

Работает ли Grove с Codex и другими агентами?

Рабочее пространство — обычный каталог, поэтому любой CLI-агент можно запустить в нём самостоятельно. Сам Grove запускает, показывает и переносит только сессии Claude Code.

Можно ли возобновить сессию из другого каталога?

Да. Grove показывает сессии всех проектов и возобновляет каждую командой claude --resume в её собственном каталоге.

Почему macOS блокирует первый запуск?

Grove подписан ad hoc и не нотаризован Apple. Один раз откройте Системные настройки → Конфиденциальность и безопасность и нажмите Все равно открыть; по шагам это описано в разделе «Первый запуск».

На каких Mac работает Grove?

На Mac с Apple silicon и macOS 26 или новее.

Grove бесплатный и с открытым кодом?

Да, под лицензией GNU GPL v3. Версия 0.2.0 и более ранние выходили под лицензией MIT.

Работает с cmux или Terminal.app

Grove построен вокруг cmux: он открывает каждую сессию в отдельном рабочем пространстве cmux и в один клик переводит вас к запущенной сессии. Terminal.app тоже подходит. В окне запуска, которое открывается по кнопке New Claude, по шестерёнке у закрытой сессии и по клику на закрытую сессию на экране Projects, есть вариант Open in: Terminal, а сессию, запущенную в Terminal.app, Grove умеет вывести на передний план. Все остальные кнопки, которые запускают или возобновляют сессию, например Resume, Resume as… и Add & log in, открывают её в cmux.

Рабочее пространство — обычный каталог, так что Claude Code можно запустить в нём и самостоятельно, из любого терминала.

Установка Grove

Grove бесплатный и с открытым исходным кодом. Нужен Mac с Apple silicon и macOS 26 или новее.

Через Homebrew

Приложение для строки меню 

brew install --cask efim0v/tap/grove

Утилита командной строки grove, если она вам нужна 

brew install efim0v/tap/grove-cli

Из релиза

Скачайте Grove.zip из последнего релиза, распакуйте и перенесите Grove.app в /Applications. В релизе также есть grove-cli.zip с утилитой командной строки и SHA256SUMS.txt.

Проверьте скачанные файлы 

shasum -a 256 -c --ignore-missing SHA256SUMS.txt

Первый запуск

Grove подписан ad hoc и не нотаризован Apple, поэтому macOS блокирует первый запуск. Это касается и установки через Homebrew: он ставит атрибут карантина macOS на скачанные cask-пакеты.

  1. Откройте Grove из папки «Программы» — macOS его заблокирует.
  2. Откройте Системные настройки → Конфиденциальность и безопасность, найдите сообщение о Grove, нажмите Все равно открыть и подтвердите кнопкой Открыть.
  3. Нажмите на значок дерева в строке меню, откройте Settings, нажмите Add project… и выберите каталог, в котором лежат ваши репозитории. Рабочие пространства создаются в ~/Workspaces/<project>/<name>, если вы не поменяете шаблон.

Или снимите атрибут карантина сами — с приложения и с бинарного файла grove, если скачали его через браузер:

xattr -dr com.apple.quarantine /Applications/Grove.app
xattr -d com.apple.quarantine grove

macOS может также попросить разрешить Grove управлять cmux или Терминалом (Системные настройки → Конфиденциальность и безопасность → Автоматизация).

Grove распространяется под лицензией GNU GPL v3; версия 0.2.0 и более ранние выходили под лицензией MIT.

Что Grove меняет на вашем Mac

Grove работает внутри собственных папок Claude Code. Здесь перечислено всё, что он там меняет, и как это откатить.

Чего Grove не делает. Он не читает учётные данные Claude Code: вход в аккаунты и лимиты — забота Brow. В нём нет телеметрии, собственных сетевых запросов он не делает, а его команды git никогда не выполняют fetch, pull или push.

Строка состояния в каждом аккаунте

При запуске Grove направляет statusLine.command в settings.json каждого аккаунта на небольшой скрипт-обёртку в ~/Library/Application Support/Grove/bin/. Обёртка сохраняет то, что Claude Code передаёт в строку состояния (модель, контекст, стоимость), в папку grove/usage/ этого аккаунта, а затем запускает вашу прежнюю команду с теми же входными данными, так что ваша строка состояния продолжает работать.

Stop рядом с monitoring на экране Accounts возвращает вашу команду на место.

Связанные аккаунты пользуются общими папками сессий

Аккаунт становится связанным, когда вы нажимаете Link to shared store на экране Accounts, переносите одну из его сессий в общее хранилище или впервые возобновляете сессию от имени другого аккаунта. После этого его папки file-history, tasks и session-env, а также projects/<workspace> каждого затронутого рабочего пространства становятся символическими ссылками внутрь ~/.claude.

Всё, что при этом было бы перезаписано, сначала переносится в <account>/grove-backup/. Учётные данные, настройки и плагины никогда не становятся общими.

Migrate to… записывает данные в другой аккаунт

Помимо файлов самой сессии, Migrate to… переносит в целевой аккаунт запись этого проекта из .claude.json, несколько ключей settings.json (например, включённые плагины, модель и тему) и плагины исходного аккаунта, объединяя их с тем, что там уже есть. Существующие данные целевого аккаунта он никогда не перезаписывает.

Зеркало транскриптов переживает очистку Claude Code

Grove хранит жёсткую ссылку на транскрипт каждой сессии в ~/.claude/grove/transcripts/ и восстанавливает пропавший из аккаунта транскрипт, даже если вы удалили его сами. Пока исходный файл существует, жёсткая ссылка не занимает лишнего места на диске. По умолчанию зеркало хранит транскрипты до 90 дней и в пределах 500 МБ.

Purge на экране Sessions удаляет транскрипт насовсем. Чтобы оставить хранение на усмотрение Claude Code, выключите Keep a backup of every session в Settings → Transcript safety-net, а затем удалите ~/.claude/grove/transcripts/.

Отметка о первом запуске в других папках аккаунтов

Прежде чем запустить Claude Code в папке аккаунта, отличной от ~/.claude, Grove выставляет hasCompletedOnboarding в .claude.json этой папки и копирует вашу тему из ~/.claude.json, если в папке её нет. Поэтому сессия не открывает мастер первого запуска Claude Code.

Собственные файлы Grove

В ~/Library/Application Support/Grove/ лежат настройки Grove (config.json), обёртки строки состояния (bin/) и статистика кода (stats/).

Рабочие пространства — это обычные git worktree и ветки в ваших репозиториях.

Как откатить эти изменения
  1. На экране Accounts нажмите Stop рядом с monitoring у каждого аккаунта. Grove вернёт сохранённую команду строки состояния или удалит ключ, если команды не было.
  2. Закройте Grove и удалите его: brew uninstall --cask grove (и brew uninstall grove-cli для утилиты командной строки) или перенесите Grove.app в Корзину. Команда defaults delete dev.artemefimov.grove3 удаляет его настройки.
  3. Удалите ~/.claude/grove/ (зеркало транскриптов и данные строки состояния), папку grove/ в каждой из остальных папок аккаунтов и ~/Library/Application Support/Grove/. Транскрипт, который сохранился только в зеркале, исчезнет вместе с ним. Если пользуетесь Brow, оставьте в последней папке oauth-usage-ledger.json: это файл Brow.
  4. Связанные аккаунты продолжают работать и без Grove. Прежде чем удалять папку grove-backup/, просмотрите её содержимое.
  5. Рабочие пространства остаются на месте: это git worktree. Чтобы удалить рабочее пространство, выполните git worktree remove в каждом его репозитории, а затем удалите его каталог.

Brow показывает, у какого аккаунта есть запас

Brow живёт в чёлке MacBook и показывает лимиты всех ваших аккаунтов Claude. Grove переносит работу между аккаунтами, а Brow подсказывает, у какого аккаунта есть запас. Каждое приложение работает и само по себе, но задуманы они как пара. В руководстве Brow (на английском) рассказано, как пользоваться несколькими аккаунтами Claude Code на одном Mac.
